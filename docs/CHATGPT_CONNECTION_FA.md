# اتصال ChatGPT

در بررسی واقعی ۱۳ اکتبر ۲۰۲۶، حساب کاربر در UI با برچسب Pro و گزینهٔ **Add custom MCP server** دیده شد. فرم فقط باز شد؛ ثبت endpoint و grant OAuth هنوز انجام نشده است. این وضعیت از راهنمای قدیمی داخل ZIP استنتاج نشده است.

مرجع جاری OpenAI: [Custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server) و [Plugins quickstart](https://developers.openai.com/plugins/quickstart). نام منو یا دسترسی طرح ممکن است تغییر کند؛ UI همان حساب در زمان اتصال ملاک است.

پس از تأیید deployment، در ChatGPT بخش Plugins را باز کنید، Add custom MCP server را انتخاب کنید و URL واقعی HTTPS با مسیر `/api/mcp` بدهید. روش احراز OAuth است. در صفحهٔ Life OS با حساب مالک وارد شوید، scopeهای لازم را بخوانید و grant را تأیید کنید. برای شروع خواندن کافی است؛ نوشتن باید scope اختصاصی داشته باشد.

دادهٔ کاری خصوصی به ChatGPT فقط در محدودهٔ ابزار و grant انتخاب‌شده منتقل می‌شود. ثبت plugin و تأیید OAuth یک تغییر دسترسی امنیتی است؛ مرحلهٔ نهایی باید با تأیید لحظه‌ای مالک طبق سیاست browser automation انجام شود. بازکردن فرم به معنی اتصال موفق نیست.

آزمون اتصال: ابتدا ابزارها را فهرست کنید؛ یک task ساختگی بسازید، همان operation ID را retry کنید و فقط یک رکورد ببینید؛ آن را در UI بازخوانی کنید و بعد آرشیو کنید. آزمون تولید باید هیچ deadline یا رابطهٔ ساختگی به دادهٔ واردشده اضافه نکند. خطای توکن منقضی/فقط‌خواندنی/بدون ورود باید رد شود.

اگر اتصال ChatGPT کامل نشد، client عمومی MCP با OAuth و REST مالک همچنان مسیر مستقل هستند. AI داخل برنامه فقط با provider واقعاً متصل و اعتبار کافی فعال است؛ اینها جای proof اتصال ChatGPT را نمی‌گیرند.

## آخرین محدودیت اجرا

در ۱۴ اکتبر ۲۰۲۶، موجودی مرورگر و یک تلاش مجدد محدود با خطای بارگذاری request-header policy متوقف شدند. فرم قبلاً آماده‌شده در این بررسی قابل دسترسی نبود؛ ثبت اتصال یا اعطای scope انجام نشد. پس از بازگشت دسترسی مرورگر، ابتدا فرم و scopeها دوباره خوانده شوند و فقط در لحظهٔ اقدام طبق سیاست ابزار تأیید مالک گرفته شود. نتیجهٔ SDK عمومی جای آزمون داخل ChatGPT را نمی‌گیرد.
