# Architecture and delivery decisions

1. **One canonical PostgreSQL domain.** Browser, REST, remote Streamable HTTP MCP and AI plans call the same owner-scoped commands/queries. Stable source text IDs are preserved, revisions reject stale writes, transaction/preview/idempotency records produce an append-only audit. PostgreSQL is the production persistence layer; PGlite is isolated test infrastructure only. Detailed graph decisions and measured limits are in `DECISIONS_DOMAIN.md`.
2. **Single owner with real OAuth clients.** Better Auth handles owner login and PKCE consent. Provider-issued JWTs are issuer/audience-bound; database owner/session and requested scopes remain mandatory. Cookie mutations require exact Origin. DPoP is disabled until replay storage is implemented. Anonymous dynamic client registration does not grant private access or owner consent.
3. **Separate workflow status and derived readiness.** ALL/ANY groups, hard/soft edges, Done-only qualification, explicit human waivers and independently tracked hierarchy/checklists follow the V2 contract. No deadline cascades or historical graph inference occurs. Task templates remap internal identities.
4. **Read-only source preservation.** Google remains a migration/reference source. All six tabs, original Drive IDs/bytes/parents, versions, unknown attrs and original Activity are retained. Later source/destination differences are quarantined. Existing Google pointers cannot claim successful archive/restore through SQL-only labels; provider operations fail closed without actual authority and verified moves.
5. **Private immutable bytes.** New uploads use a private Blob store, owner-specific immutable keys, provider checksum verification and attachment-only delivery. All existing account stores are suspended by quota; this is an external connection blocker, not permission to expose bytes or reuse another application's credentials. Existing external Google references remain available through their original permissions.
6. **Date and time semantics.** Date-only deadlines are local dates. Exact instants retain source timezone meaning. Manual DST gaps are rejected and folds require an explicit choice. Recurrence resolves each date's IANA offset, preserves exact seconds, excludes exceptions and uses exclusive all-day end. Work hours are elapsed minutes split at local midnight; Jena/Seewiesen exports preserve literal descriptions. Holiday code is adapted under the Work Planner MIT license.
7. **AI is preview-first and financially bounded.** Records are untrusted, context is selected/clipped/byte-bounded, actual checklist/file IDs are grounded, nested IDs/authorization flags are validated and writes wait for an owner-bound plan execution. Provider URL validation precedes private reads/reservations. A model-matched price cap verified within seven days is required; actual prompt UTF-8 upper bounds plus output ceiling determine atomic daily reservations. No live provider call or charge is claimed when credit/configuration is absent.
8. **Portable recovery preserves retry history.** Backups retain graph/checklists/raw source metadata plus accepted idempotency outcomes; otherwise an old client retry could duplicate a restored record. Fresh isolated restore validates checksums and adds a new audit event without rewriting historical events. Credentials/sessions remain separate; private exports can be encrypted with authenticated AES-GCM/scrypt.
9. **Real team, exclusive paths, central release.** Four actual parallel agents cover orchestration, domain/database, UX, and migration/integrations/independent QA. The shared checkout uses explicit path ownership and coordinator-only commits/deployment/production cutover. Google originals and the separate Work Planner reference remain read-only. Do not claim thirteen independently running agents merely because the handoff describes thirteen roles.
10. **Evidence is layered.** Mocked transport proves code boundaries; actual local OAuth/MCP proves protocol/auth behavior; isolated PostgreSQL proves SQL contracts; multi-connection staging proves races; only the observed production URL can prove hosting and persistence. ChatGPT account UI/installation is separate from generic MCP success. External quota/OAuth/billing gates remain explicit and cannot be replaced by fake data or guessed URLs.
