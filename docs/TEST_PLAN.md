# Verification plan

Tests use synthetic identifiable records. The private old Google ledger is only read and rehearsed in disposable databases; it is never used for destructive feature experiments. Shared UI/REST/MCP/AI operations must exercise the same canonical domain, owner checks, revisions and idempotency journal.

Calendar runtime contracts explicitly mock owner-account lookup, OAuth refresh and Google/iCal transport; they exercise exact read scope, stable read-only IDs, independent source selection, response/page/event bounds and secret-free errors. Backup-job contracts explicitly mock database/domain/Blob while running real AES-GCM encryption/decryption, including uncertain accepted upload and inconsistent checksums. Actual JWT human-authority negatives in `tests/security/http-auth-human-authority.test.ts` require the isolated staging server and owner consent; they must not be marked PASS merely because the opt-in suite is skipped.

## Failure handling and ownership

Reproduce a defect with the narrowest meaningful independent test, notify the owning team, repair, then rerun the affected layer and its contract consumers. Do not weaken a failing assertion or replace an external failure with a mock success. Mocks exist for unavailable provider transport and orchestration branches; actual OAuth/HTTP and real PostgreSQL tests remain separate.

Production experiments create only clearly synthetic records and archive only those fixtures after proof. A real source task is not completed merely for a smoke test. A source re-read/checkpoint expires after ten minutes; regenerate it immediately before the coordinator's actual migration. Never upload private dumps or genuine owner screenshots to public CI artifacts.
