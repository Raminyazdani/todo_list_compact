# محدودهٔ فعلی با دستور مستقیم مالک

در ۱۴ اکتبر ۲۰۲۶ مالک سه تغییر را خواست: استفاده از Neon، کنارگذاشتن موقت AI داخل برنامه، و دسترسی همین دستیار Codex از طریق MCP. این دستور بر الزامات قدیمی AI زنده، اعتبار مدل و نصب اتصال در ChatGPT مقدم است. شواهد قبلی مهاجرت، گراف و بازیابی همچنان تاریخی و معتبرند؛ برای این تغییر دوباره اجرا نمی‌شوند.

دیتابیس دائمی از قبل روی PostgreSQL در Neon است. فضای فایل جدید و پشتیبان رمزنگاری‌شده برای Neon Object Storage پیاده و منتشر شده‌اند. CHECK افزایشی ابتدا روی staging و سپس تولید با پشتیبان مستقل اجرا شد و فایل‌ها، نسخه‌ها و لینک‌های موجود تغییر نکردند. provider تولید روی Neon انتخاب شده ولی نوشتن فایل هنوز فعال نیست. ارجاع‌های اصلی Google Drive و فایل‌های قبلی Blob provider خود را حفظ می‌کنند. اعتبارنامهٔ S3 فقط روی سرور می‌ماند؛ endpoint برنامه دانلود را پس از کنترل مالکیت انجام می‌دهد. فعال‌سازی PUT به بررسی واقعی عدم بازنویسی object وابسته است؛ آزمون مصنوعی SDK جای این شاهد را نمی‌گیرد.

AI داخل برنامه فعلاً خاموش است: لینک، فرم و widget آن نمایش داده نمی‌شوند و endpointهای AI پس از احراز هویت درخواست را با FEATURE_DISABLED رد می‌کنند. ورود از فرم واقعی سایت، صفحهٔ غیرفعال AI، API آن، تنظیمات MCP و حداقل رمز هشت‌کاراکتری روی نسخهٔ منتشرشده تأیید شد؛ هر سه فایل اصلی بدون ورود401/noRedirect بودند و هیچ write تجاری در این بررسی انجام نشد. MCP مستقل است و محدودیت scope، revision، idempotency و audit دامنه را حفظ می‌کند.

رمز خواسته‌شده روی حساب موجود تنظیم شد. ورود واقعی HTTPS موفق و نشست‌های قبلی لغو شدند. خود رمز در این سند، Git یا گزارش عمومی ثبت نمی‌شود. فرم و سرور تنظیم رمز، حداقل هشت کاراکتر را می‌پذیرند.

اتصال `life_os` در تنظیمات محلی Codex ثبت شد و login بومی OAuth موفق بود. scopeهای معمول کار، پروژه، فایل، تقویم، ساعت کار و Activity اعطا شدند؛ admin و backup در این اتصال نیستند. این شاهد هنوز به معنی بارگذاری ابزار در چت جاری نیست: runtime همین چت، سرور تازه را نشناخت. Codex باید یک‌بار دوباره باز و همین چت ادامه داده شود؛ سپس یک خواندن واقعی MCP لازم است.

فعال‌سازی فضای فایل منتظر ورود مالک به حساب موجود Neon است. CLI نصب است اما profile احراز‌شده ندارد. مالک `neon login` را محلی اجرا می‌کند؛ کلید یا رمز را در چت نمی‌فرستد. پس از آن، همان پروژه و branch تولید باید از endpoint فعلی تأیید شود، bucket خصوصی و credential محدود ساخته شود، آزمایش واقعی conditional PUT و دانلود بی‌مجوز انجام شود و محیط سرور تنظیم گردد. هیچ پروژهٔ جایگزین، خرید یا تغییر منبع اصلی برای دورزدن این مرحله مجاز نیست.

نسخهٔ نهایی d347404 با [CI 38574338435](https://github.com/Raminyazdani/todo_list_compact/actions/runs/38574338435) کامل موفق و deployment تولید READY است: ۴۶۲ آزمون coverage، ۱۲ PostgreSQL واقعی، ۲۴ مرورگر، کاتالوگ ۱۳۰ ابزار MCP و همهٔ آزمون‌های HTTP/OIDC/rate-limit/انقضای واقعی توکن پاس شدند. ۲۸ opt-in و سه سناریوی مرورگر skip صریح دارند. نتیجهٔ دقیق در [BUILD_PROGRESS.json](BUILD_PROGRESS.json) است. تا تکمیل شاهد زندهٔ Neon و بارگذاری واقعی ابزار MCP، این دو بخش تحویل کامل اعلام نمی‌شوند. اتصال تقویم خارجی و ثبت passkey/PWA همچنان مراحل جداگانهٔ مالک‌اند.
